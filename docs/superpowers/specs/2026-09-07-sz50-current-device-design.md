# SZ50 当前设备功能合并与适配设计

**日期**：2026-09-07  
**目标分支**：`sz50`   
**基线**：fork `main`（`5d706ae`）  
**参考实现**：上游 `SZ50`（`ce5ff95`）

## 目标

在 fork 的 `sz50` 分支中保留通用版 `main` 的全部功能和修复，恢复上游 SZ50 专用的 LED、按键、WiFi、恢复出厂和设备接入管理能力，并使这些功能适配当前连接的 UDX710 `marlin3e` 设备。

## 设备事实

本次适配只根据当前设备的只读检查结果设计：

- CPU 架构为 `aarch64`，内核为 `4.14.98`，设备树型号为 `Spreadtrum UDX710_module_marlin3e`。
- oFono 暴露 `/ril_0` 和 `/ril_1`，当前 `/ril_0` 在线、`/ril_1` 离线。
- 蜂窝数据接口为 `sipa_eth0`；设备同时存在 `wlan0`、`wlan1` 和 `usb0`。
- 当前 hostapd 运行在 `wlan1`，配置文件为 `/mnt/data/hostapd_wlan1.conf`。
- LED 节点为 `red_led`、`green_led`、`blue_led` 和 `sc27xx:red/green/blue`，不存在 SZ50 分支使用的 `lte_*`、`nr_*`、`wifi_*` 节点。
- 产品是外部供电的路由器形态，没有内置电池；`/sys/class/power_supply` 为空，因此充电控制必须报告为不适用，不应显示为故障电池。
- Type-C 控制器是双角色 DWC3，当前 gadget 为 `0x2dee:0x4d51`，组合包含 RNDIS、ADB 和串口功能；当前配置使用 `rndis.gs4`，不能套用通用版的 `0x1782:0x4038/4039/4040` 判断。
- 设备有 RJ45 物理接口。当前固件存在 PHY 电气链路，但没有 `eth0`、`/dev/seth_lte` 或 modem 侧以太网消费者；代码必须区分“物理接口存在”和“当前固件可用”，并在出现可用有线接口后自动识别、加入路由桥接。
- Type-C 主机侧支持通过内建 `r8152` 驱动接入 RTL8152/RTL8153 USB 网卡；代码应识别新增有线网卡，但不把 HDMI、存储或其他 USB 设备误判为网络接口。

## 方案

### 代码基线与功能来源

以 fork `main` 为唯一主线基线，不直接合并两个无共同历史的分支。仅从上游 `SZ50` 移植以下专用能力：

- 后端：`led`、`power_key`、`wifi`、`factory_reset` 模块及其 HTTP 路由。
- 前端：`WifiManager.vue`、`DeviceManager.vue`，并把它们接入通用版导航、状态和 API 调用。
- 构建：把移植模块加入 `src/Makefile` 和 CI 构建；目录结构继续使用通用版 `src/include` 头文件布局。

通用版已有的认证、APN、插件、脚本、Rathole、IPv6 代理、网络接口、密保和 USB 页面全部保留。所有新增硬件路由沿用通用版认证中间件。

### 设备能力探测

新增一个小型 `device_profile` 模块，集中读取运行时路径和能力，避免各模块重复硬编码：

- 从运行中的 hostapd 命令行和配置文件确定 WiFi 接口及配置路径，优先得到当前 `wlan1`，没有 hostapd 时使用存在的无线接口作为配置目标。
- 枚举 `/sys/class/leds`，按颜色建立可用 LED 映射；只使用存在且可写的节点。
- 检测电池目录、USB gadget 节点、Type-C 角色、在线 oFono modem 和有线接口，生成能力结果和不可用原因。
- 选择在线 modem 路径供需要主动 modem 的功能使用；找不到在线 modem 时保留 `/ril_0` 作为只读回退。
- 选择 `sipa_eth0` 作为首选数据接口，并在缺失时从运行状态中的蜂窝接口回退。
- 将 RJ45 和 Type-C 外接网卡分别标记为 `physical_present`、`interface_present`、`usable` 三种状态；当前设备的 RJ45 为物理存在但系统侧不可用，Type-C gadget 的 RNDIS 为可用，Type-C 外接网卡只有在枚举后才标记为可用。

通过 `/api/capabilities` 返回这些结果。前端先读取能力再显示或禁用硬件控制项；不支持项返回稳定的 HTTP 错误和原因，不执行猜测性的系统写操作。

### 部署边界

构建产物继续放在 `/home/root/6677`。启动脚本改用设备已有的 `start-stop-daemon`（不可用时返回明确错误），保证脱离 ADB shell；本次只提交项目内脚本，不修改当前设备的根分区启动文件，也不在开发验证中切换 USB 模式、写 LED 或重启设备。

## 测试与验收

### 测试

- 先为 `device_profile` 的接口选择、LED 映射、无电池和 USB 能力判定写主机侧失败测试，再实现最小代码使其通过。
- 用 C 主机测试编译检查设备探测逻辑；用 shell 语法检查启动脚本。
- 用 `pnpm` 构建前端，使用 CI 的交叉编译配置检查后端源文件和链接清单。
- 对生成的路由清单做静态检查，确认通用版与 SZ50 专用接口均存在。

### 验收条件

1. fork 的 `sz50` 分支包含 `main` 的通用功能以及 SZ50 专用后端/前端功能。
2. 当前设备上 `wlan1`、`sipa_eth0`、颜色 LED 和在线 `/ril_0` 能被正确识别。
3. 无电池和不兼容 USB 模式不会导致服务启动失败，也不会执行错误路径写入。
4. 未认证 API 仍遵循通用版白名单，新增控制 API 需要 Token。
5. 主机测试、前端构建、后端 CI 构建配置和静态路由检查均通过。
6. 完成验证后推送到 `https://github.com/wuhao1477/UDX710-TOOLS` 的小写 `sz50` 分支。

## 不在本次范围内

- 不刷写整机固件，不修改 NAND/UBI 镜像。
- 不在设备上启用或切换 USB ECM/NCM/RNDIS。
- 不把当前 RJ45 的物理存在误报为已经可用；若固件没有 `seth_lte` 或有线网卡，页面显示原因并保留只读状态。
- 不把当前设备的序列号、密码、MAC 或其他实例数据写入源码和测试夹具。
- 不重写与本次功能无关的通用版业务模块。
